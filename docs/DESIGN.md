## 2. PDF 대비 정정 사항 — 기어(P단)는 읽을 수 있다

PDF는 "Vehicle SDK에 기어 없음"이라고 판정했지만, 캐시된 **Vehicle 2.3.2 AAR에 `Gear` API가 있다**:

```kotlin
vehicle.getGear().getCurrentGearSelectionState(onComplete: (VehicleGear) -> Unit, onFailed)
vehicle.getGear().registerGearSelection(GearSelectionListener { gear -> ... })  // onSelected(VehicleGear)
// VehicleGear.GEAR_PARK / GEAR_DRIVE / GEAR_REVERSE / GEAR_NEUTRAL / GEAR_UNKNOWN ...
```

→ 시작 조건과 자동 부상을 **실제 기어 값으로** 구현한다. 다만 필요한 퍼미션(`CAR_DRIVE`로 추정)과 에뮬레이터 동작은 아직 검증 전이다.
→ 안전장치로 PDF의 대안도 유지한다: 기어 읽기가 실패하면 주행 규제 변경을 이탈 신호로 쓰고, 시작은 사용자 확인 버튼으로 받는다.

그 밖에 확인한 API:
- `Door.getDoorLockState(DoorArea, ...)`, `registerDoorLockState`, `registerDoorPosition`
- `Window.getCurrentWindowPosition(WindowArea, ...)`
- `EvBattery.getEvBatteryStateOfCharge`, `getEvChargeSwitchState`, `registerEvChargePortOpen`
- `Odometer.getTripCurrentDrivingDistance` (필요 시)
- 퍼미션 상수: `PleosPermission.CAR_DOORS / CAR_WINDOWS / CAR_ENERGY / CAR_DRIVE ...`

## 3. 화면·플로우

```
홈 ──바로 쉬기──▶ 02 시간 선택 ──▶ 03 해치(안전 확인 + 잠수 연출) ──▶ 04 휴식(잠항 중)
 │                                   [바로 시작] (연출만 건너뜀)          │
 │                                                                     ├─ 1분 전 예고(05)
 │                                                                     ▼
 ├─ 지층 보기 ◀──────────────────────────────────────── 06 결과(+지층 모션)
 ├─ 주말 항해 제안 카드 (NaviHelper, 조건부)                 ▲
 ├─ 충전 중 휴식 제안 카드 (EvBattery, 조건부)               │
 └─ 테스트 메뉴                         P단 이탈 / 문 열림 ──▶ 08 자동 부상 결과 (실제 머문 시간)
```

| # | 화면 | 핵심 상태·동작 |
|---|---|---|
| 01 | 홈 | 바로 쉬기, 오늘 기록 요약, 조건부 제안 카드, 지층 보기 진입 |
| 02 | 시간 선택 | 프리셋(예: 5/10/15/20분) — 시간 트랙은 **표시 전용**(손잡이 없음) |
| 03 | 해치 | 체크 항목: P단 · 문 잠김 · 창문 닫힘 · 배터리. 미충족 시 안내. 버튼명 **"바로 시작"** |
| 04 | 휴식 | 남은 시간, 바다 소리, 볼륨, "마치기". 화면 꺼져도 Foreground Service로 유지 |
| 05 | 1분 전 예고 | 오버레이 + 녹음 음성 |
| 06 | 결과 | 머문 시간, 지층 +1 모션, 한마디 입력(키보드) |
| 07 | 지층 보기 | 쌓인 지층 시각화 + 항해 일지 목록 (현재 팝업만 뜨는 문제 수정) |
| 08 | 자동 부상 | 이탈 사유(P단 이탈/문 열림) + 실제 머문 시간 |
| T | 테스트 메뉴 | 기어·문·창문·배터리·내비 유무·주행 규제를 Fake로 바꿔 각 예외 시연 |

### PDF 피드백 반영
1. 시연 시드: 대표 흐름은 **"오늘 첫 기록"**으로 끝나도록 초기 데이터 구성 → 지층 +1 모션 노출
2. P단 이탈 → 일반 결과가 아닌 **08 자동 부상** + 실제 머문 시간
3. "지층 보기" → 실제 지층 화면
4. 해금 기준을 낮춤 (값은 `UnlockConfig`로 분리해 조정 가능하게) — 구체 수치는 컨펌 필요
5. 시간 트랙 손잡이 제거, 6. "건너뛰기" → "바로 시작"
8. 용어 축소 — 컨펌 필요 (§6)
9. 최소 캡션 20sp 이상을 디자인 토큰으로 강제

## 4. 아키텍처

- 단일 Activity + **Jetpack Compose** + Navigation Compose (현재 베이스는 View/XML → 교체 제안, §6)
- MVVM: 화면별 `ViewModel` + `StateFlow`
- DI 없이 수동 주입(`AppContainer`) — 공모전 규모에 맞춤

```
pleos.jamhang
├─ JamhangApp.kt                 // AppContainer 생성
├─ MainActivity.kt               // Compose host, NavHost
├─ vehicle/
│  ├─ VehicleStateSource.kt      // interface: gear/doorLocked/doorOpen/windowsClosed/soc/charging Flow
│  ├─ PleosVehicleSource.kt      // Vehicle SDK 구현 (콜백 → callbackFlow)
│  └─ FakeVehicleSource.kt       // 테스트 메뉴용, 값 수동 변경
├─ car/
│  └─ DrivingRestriction.kt      // CarUxRestrictionsManager 래핑
├─ navi/
│  └─ NaviBridge.kt              // NaviHelper 래핑 (미탑재 감지)
├─ session/
│  ├─ DiveSession.kt             // 상태 머신: Idle→Hatch→Diving→Warning→Surfaced(Normal|Auto(reason))
│  ├─ DiveService.kt             // Foreground Service: 타이머·오디오·차량 이벤트 감시
│  └─ SeaSoundPlayer.kt          // MediaPlayer + AudioFocus
├─ data/
│  ├─ JamhangDb.kt / DiveLogDao  // Room: 항해 일지
│  └─ UnlockConfig.kt
└─ ui/
   ├─ theme/                      // Figma 토큰 (§7)
   ├─ home/ select/ hatch/ diving/ result/ strata/ surface/ testmenu/
```

**핵심 상태 머신** (`DiveSession`, Service가 소유):
- `Diving` 중 `gear != PARK` 또는 `doorOpen` → `Surfaced.Auto(reason, elapsed)`
- 종료 시각 1분 전 → `Warning` → 0초 → `Surfaced.Normal`
- Audio focus loss → 일시정지 (타이머는 계속, 종료 시각 고정)

- 앱 창: **가로 1700×1184** (Connect-S 17″, 왼쪽 840은 Driving View), 창 라운드 40, 상단 중앙 window bar(시스템 UI, 120×8).

- 02/03 헤더: ‹ 뒤로 + 제목 (Title/Large), 높이 ~160, 아래 1px 디바이더(`divider/secondary`).
- System UI(상태바 96, GNB 160)가 앱 위에 겹칠 수 있음 → 내용은 창 안쪽 기준으로 배치.
